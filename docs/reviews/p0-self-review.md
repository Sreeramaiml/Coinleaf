## 3. Deviations from PS / ARCH

| # | Deviation | Reason |
|---|---|---|
| D1 | The demo ledger's key is in a 0600 file next to the demo DB, not in the Keychain | The demo holds only synthetic data, and this keeps the demo and the tests from writing to your Keychain. The real ledger uses the Keychain. |
| D2 | `FINASSIST_KEYSTORE=file` environment override | For tests and CI only, so tests never touch the Keychain. Default is unchanged. |
| D3 | SQLCipher key set as a raw key by a connection factory, not through the `sqlite+pysqlcipher` URL | The dialect would put the key in the URL and run PBKDF2 on every connection; the key is already 256 random bits. |
| D4 | `query_transactions` takes the period as text and resolves it in code | Saves a model round trip per question; dates are still resolved only by code (ARCH §9.3), and results state them. `resolve_period` remains available. |
| D5 | `add_transaction` asks the owner to confirm (ARCH §10.4 listed it as `write`) | ARCH §7.9 also says manual entries are echoed before saving; a confirm gate does both. |
| D6 | Import preview includes a **file check** (statement opening + rows = closing) | A cheap parse sanity check ahead of P1's ledger reconciliation (ARCH §7.7). |
| D7 | Import refuses a statement whose last-4 belongs to a different account | Found while testing: a statement could otherwise be imported into Cash by mistake. |
| D8 | Grounding exempts small integers and years only when they are plain numbers (not ₹ amounts or percentages) | Found by a test: "up 12%" would otherwise pass unchecked. |
| D9 | Demo v1: no transfers, card bill payments, ATM withdrawals, investments or refunds; 1,134 rows, not ~1,300 | Without P1's transfer detection every such row would be miscounted. As a side effect the demo card balance grows without being paid. v2 in P1 adds these flows and brings the dataset over 1,500 rows (PS §12). |
| D10 | Only account nicknames are sent to the model, including in import results | Found in review: the import result first carried the full account name. |
| D11 | Ruff allows string literals up to 125 characters; the formatter wraps code at 110 | Long messages read better unsplit. |

## 4. Assumptions

- Statements cover whole days (fingerprint occurrence index, ARCH §7.4). Confirm with real layouts in P1.
- A month named without a year means its most recent occurrence that has started; current periods are clipped to today. Covered by tests.
- Uncategorised debits count as expense and uncategorised credits as income (ARCH §9.2). In P0 almost everything is uncategorised, and every answer says how much.
- Defaults accepted for ARCH §21 Q1 (A-1 to A-5), Q3 (cloud with redaction), Q6 (Python 3.14) and Q7 (`finassist`), because the build was requested without answers.

## Addendum (2026-11-23): first local run with a real Gemini key

Bugs found and fixed, each with tests:
1. **The stored key contained a terminal escape sequence** (`ESC[C`, a right-arrow key press at the hidden prompt). Google rejected every request with an HTML 400. Keys are now cleaned on save and on read (`db/keys.clean_api_key`), and a key with impossible characters is refused.
2. **Google's HTML error page was shown raw.** HTML 400, 404 (model not available to this key) and 503 (high demand) now give plain explanations.
3. **No retries for transient errors.** The Gemini client now retries 500/502/503/504 with backoff (`llm.retries`, default 3); 429 is not retried.
4. **`FINASSIST_CONFIG` was ignored** by the CLI (the default config path was always passed). Fixed.

Live result on `gemini-3.5-flash-lite`: see verification log V7a-g. Gemini Flash and Gemini 4 models were returning 503 "high demand" for this key during the session.
